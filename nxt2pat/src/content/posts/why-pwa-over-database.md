# Zero Database, Zero Latency: สถาปัตยกรรมไร้ฐานข้อมูลสำหรับพอร์ตโฟลิโอวิศวกรรม

## 1. จุดเริ่มต้นและปัญหาของสถาปัตยกรรมแบบดั้งเดิม

เมื่อนักพัฒนาส่วนใหญ่เริ่มต้นสร้างเว็บไซต์พอร์ตโฟลิโอส่วนตัว มักจะหยิบเครื่องมือยอดนิยมที่มีความซับซ้อนสูงมาใช้งานโดยอัตโนมัติ เช่น ฐานข้อมูลแบบคลาวด์ (Cloud Database อย่าง Supabase หรือ Firebase), สถาปัตยกรรม Serverless Functions, หรือระบบจัดการเนื้อหา (CMS) ภายนอก

ทว่าสำหรับเว็บไซต์แสดงผลงานทางวิศวกรรมและบทความทางเทคนิค สถาปัตยกรรมแบบ Dynamic Server-Client กลับก่อให้เกิดปัญหาตามมาหลายประการ:

1. **ปัญหา Cold Start Latency**: เซิร์ฟเวอร์เลสฟังก์ชันที่ไม่ได้ถูกเรียกใช้งานเป็นเวลานาน จะใช้เวลาปลุกตัวเอง (Cold Start) 1.5–3.5 วินาที ทำให้ผู้ตรวจผลงานหรือกรรมการที่กดเปิดลิงก์ต้องเผชิญกับหน้าจอโหลดที่เชื่องช้า
2. **ความล้มเหลวเมื่อไร้สัญญาณอินเทอร์เน็ต**: ในการนำเสนอผลงานภาคสนาม บนรถไฟฟ้า หรือในห้องประชุมที่มีสัญญาณอับ เว็บไซต์ที่พึ่งพา API ฐานข้อมูลจะแสดงหน้าจอสีขาวและข้อผิดพลาดทันที
3. **ภาระการดูแลรักษาระบบ (Maintenance Debt)**: การต้องคอยอัปเดต Migration Scripts, จัดการ Connection Pooling, และกังวลเรื่องโควตาฟรีของคลาวด์ ถือเป็นความซับซ้อนที่เกินความจำเป็นสำหรับเนื้อหาที่ไม่ได้อัปเดตทุกวินาที

```
┌────────────────────────────────────────────────────────┐
│             DYNAMIC BACKEND VS STATIC PWA              │
├──────────────────────────┬─────────────────────────────┤
│  Dynamic (External DB)   │  PWA Static (This Site)     │
├──────────────────────────┼─────────────────────────────┤
│  Browser ──▶ Edge Fn     │  Browser ──▶ Service Worker │
│  Edge Fn ──▶ Remote DB   │  Service Worker ──▶ Cache   │
│  Roundtrip: 400ms–2500ms │  Roundtrip: 10ms–40ms       │
└──────────────────────────┴─────────────────────────────┘
```

## 2. ทางเลือกวิศวกรรม: Static Site Generation + Serwist Service Worker

เพื่อตอบสนองแนวคิด **"CPU-First & Resilient Engineering"** พอร์ตโฟลิโอนี้จึงถูกสร้างขึ้นโดยใช้:

- **Next.js Static Site Generation (SSG)**: เนื้อหาเคสสตัดดี้และบทความทั้งหมดถูกเขียนในรูปแบบ Markdown (.md) พร้อม Metadata Frontmatter ในช่วง Build Time หน้าเว็บทุกหน้าจะถูกคอมไพล์เป็น HTML และ JavaScript ล่วงหน้า ทำให้พร้อมเสิร์ฟทันที
- **Serwist Service Worker**: เมื่อผู้เยี่ยมชมเปิดเว็บไซต์ครั้งแรก Service Worker จะทำการแคช Assets ทั้งหมด (HTML, CSS, Fonts, Images) ลงใน Local Cache Storage ของเบราว์เซอร์
- **Offline 100%**: เมื่ออยู่ในโหมดออฟไลน์ (Airplane Mode) ผู้ใช้ยังสามารถเปิดดูผลงาน อ่านบทความ และทดลองใช้งานฟีเจอร์ต่างๆ ได้อย่างลื่นไหลด้วยความหน่วงต่ำกว่า 40 มิลลิวินาที

## 3. ปรัชญาความเรียบง่าย

ความสง่างามทางวิศวกรรมคอมพิวเตอร์ ไม่ใช่การใส่เทคโนโลยีให้เยอะที่สุด แต่คือการรู้ว่า **"อะไรคือสิ่งที่ไม่จำเป็นและควรตัดออก"** เพื่อให้ระบบคงทน เรียบง่าย และพึ่งพาตนเองได้ในทุกสภาพแวดล้อม
