# DustWatch — โครงข่ายตรวจวัดและพยากรณ์มลพิษทางอากาศพลังงานต่ำ (NSC 2026)

## 1. ที่มาและเป้าหมายของโครงงาน (Motivation & NSC 2026 Objectives)

วิกฤตมลพิษฝุ่นละอองขนาดเล็ก **PM2.5 และ PM10** ในประเทศไทย โดยเฉพาะในพื้นที่ภาคเหนือและเขตอุตสาหกรรม สร้างผลกระทบเรื้อรังต่อระบบทางเดินหายใจของประชาชน อย่างไรก็ตาม สถานีตรวจวัดคุณภาพอากาศมาตรฐานของภาครัฐมักมีจำนวนน้อย มีราคาสูงระดับหลักล้านบาท และตั้งอยู่ห่างไกลกัน ทำให้ไม่สามารถสะท้อนค่ามลพิษระดับชุมชน (Microclimate Exposure) ได้อย่างแท้จริง

ยิ่งไปกว่านั้น ในพื้นที่หุบเขา ชายป่า หรือพื้นที่เกษตรกรรม มักประสบปัญหา **สัญญาณโทรศัพท์มือถือและอินเทอร์เน็ตไม่เสถียรหรือเข้าไม่ถึง** ทำให้อุปกรณ์ IoT ทั่วไปที่พึ่งพา 4G/WiFi ไม่สามารถทำงานได้

**DustWatch** จึงถูกพัฒนาขึ้นสำหรับ **การแข่งขันพัฒนาโปรแกรมคอมพิวเตอร์แห่งประเทศไทย ครั้งที่ 28 (The 28th National Software Contest: NSC 2026)** โดยมีเป้าหมายสร้างระบบตรวจวัดมลพิษทางอากาศที่:
1. **พึ่งพาตนเองได้ (Self-Sustaining & Low-Power)**: ใช้พลังงานต่ำมาก สามารถเชื่อมต่อกับแผงโซลาร์เซลล์และแบตเตอรี่ได้ต่อเนื่องยาวนาน
2. **สื่อสารระยะไกลโดยไม่ง้ออินเทอร์เน็ต (Long-Range LoRa Mesh)**: เชื่อมต่อระหว่างโหนดด้วยคลื่นวิทยุ LoRa 433 MHz ระยะทางกว่า 8.4 กิโลเมตร
3. **ทนทานต่อภาวะสัญญาณขาดหาย (Offline Resilience)**: บันทึกข้อมูลลง Flash Memory บนบอร์ดทันที ไม่สูญเสียข้อมูลแม้ตัดขาดจากเซิร์ฟเวอร์
4. **พยากรณ์ล่วงหน้าด้วย AI (Predictive Intelligence)**: ไม่ใช่แค่รายงานค่าปัจจุบัน แต่ใช้ Machine Learning พยากรณ์ระดับฝุ่นล่วงหน้า 1–6 ชั่วโมง

## 2. โครงสร้างสถาปัตยกรรมระบบ (System Architecture)

ระบบประกอบด้วย 3 ส่วนสำคัญที่ทำงานประสานกันอย่างเป็นระบบ:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        DUSTWATCH ARCHITECTURE                          │
├────────────────────────┬──────────────────────┬────────────────────────┤
│     FIELD SENSOR NODE  │     BASE GATEWAY     │   SERVER & AI BACKEND  │
│  ESP32-S3 + PMS5003    │  LoRa Receiver       │  FastAPI + InfluxDB    │
│  BME680 + LittleFS     │  WiFi / MQTT Bridge  │  XGBoost Prediction    │
└────────────────────────┴──────────────────────┴────────────────────────┘
```

### 2.1 โหนดตรวจวัดภาคสนาม (Field Sensor Node)
- **ประมวลผลหลัก**: ชิปไมโครคอนโทรลเลอร์ ESP32-S3 (Dual-Core Xtensa LX7)
- **เซนเซอร์ตรวจวัดฝุ่น**: Plantower PMS5003 ใช้หลักการกระเจิงของแสงเลเซอร์ (Laser Scattering) วัดอนุภาค PM1.0, PM2.5, PM10
- **เซนเซอร์สภาพแวดล้อม**: BME680 ตรวจวัดอุณหภูมิ, ความชื้นสัมพัทธ์, ความกดอากาศ และสารประกอบอินทรีย์ระเหยง่าย (VOCs Gas)
- **เซนเซอร์ตรวจจับเสียง**: INMP441 (I2S Digital Microphone) สำหรับวิเคราะห์ความหนาแน่นของการจราจรหรือกิจกรรมการเผา
- **โมดูลสื่อสารวิทยุ**: Semtech SX1278 LoRa Transceiver (433 MHz) พร้อมเสาอากาศ High-Gain Dipole
- **โครงสร้างกายภาพ**: กล่องป้องกันสภาพอากาศ (Weatherproof Enclosure) ออกแบบและพิมพ์ด้วย 3D Printer ใช้วัสดุ PETG ทนความร้อนและรังสี UV พร้อมช่องดักแมลงและตาข่ายกรองละอองน้ำ

### 2.2 โหนดเกตเวย์รับข้อมูล (Base Gateway Station)
- ทำหน้าที่เป็นสะพานเชื่อม (Bridge) รับแพ็กเก็ตข้อมูลจากโหนด LoRa ภาคสนามหลายตัว
- แปลงข้อมูลแล้วส่งต่อเข้าสู่เซิร์ฟเวอร์ส่วนกลางผ่านโพรโทคอล **MQTT (Message Queuing Telemetry Transport)** ผ่าน WiFi หรือเครือข่าย Ethernet

### 2.3 เซิร์ฟเวอร์และระบบประมวลผล AI (Backend & Analytics)
- **API Server**: พัฒนาด้วย Python FastAPI สถาปัตยกรรม Asynchronous ประสิทธิภาพสูง
- **Time-Series Database**: InfluxDB จัดเก็บข้อมูลเวลาตรวจวัด รองรับการเขียนและคิวรีข้อมูลกราฟิกความเร็วสูง
- **Metadata Database**: SQLite จัดเก็บการตั้งค่าสถานี ประวัติการบำรุงรักษา และพิกัด GPS
- **AI Forecasting Engine**: ใช้โมเดล Gradient Boosting (XGBoost / LightGBM) เรียนรู้จากข้อมูลย้อนหลัง (ความชื้น, อุณหภูมิ, ความกดอากาศ, ทิศทางลม, และแนวโน้มฝุ่น) เพื่อพยากรณ์ดัชนี PM2.5 ล่วงหน้า

## 3. วิธีการทำงานและกลไกเชิงวิศวกรรม (Engineering Rigor)

### 3.1 การถนอมอายุการใช้งานเซนเซอร์เลเซอร์ (Dynamic Optical Duty-Cycle)
เซนเซอร์ฝุ่นเลเซอร์ PMS5003 มีพัดลมดูดอากาศขนาดเล็กภายใน ซึ่งหากเปิดทำงานตลอด 24 ชั่วโมงต่อเนื่อง พัดลมและไดโอดเลเซอร์จะเสื่อมสภาพภายในเวลา 1–2 ปี
- **นวัตกรรมเฟิร์มแวร์**: DustWatch สั่งเปิดพัดลมเซนเซอร์ล่วงหน้าเพียง 30 วินาทีก่อนรอบการวัด เพื่อให้กระแสลมในช่องตรวจวัดนิ่งเสถียร จากนั้นทำการเก็บตัวอย่างข้อมูล 10 ค่า คำนวณค่ามัธยฐาน (Median Filter) ตัดสัญญาณรบกวน แล้วสั่งปิดพัดลมทันที
- **รอบการวัดแบบปรับตัวได้**: ในสภาวะปกติจะวัดทุก 10 นาที แต่หากตรวจพบค่า PM2.5 สูงเกินเกณฑ์เตือนภัย (> 90 µg/m³) ระบบจะปรับรอบการวัดให้ถี่ขึ้นเป็นทุก 3 นาทีโดยอัตโนมัติ

### 3.2 ความทนทานระดับออฟไลน์ (LittleFS Ring-Buffer Failover)
เมื่อโหนดภาคสนามไม่สามารถส่งสัญญาณวิทยุ LoRa ถึงสถานีแม่ได้ (เช่น เกิดคลื่นรบกวนหรือสถานีแม่ปิดปรับปรุง):
- เฟิร์มแวร์จะสลับไปบันทึกข้อมูล telemetry ลงในหน่วยความจำแฟลชของ ESP32-S3 ผ่านระบบไฟล์ **LittleFS** ในลักษณะ Circular Ring Buffer
- สามารถบันทึกข้อมูลออฟไลน์ได้ต่อเนื่องนานกว่า **30 วัน**
- เมื่อกลับมาเชื่อมต่อสัญญาณได้ โหนดจะทยอยอัปโหลดข้อมูลย้อนหลัง (Batch Synchronization) เข้าสู่เซิร์ฟเวอร์โดยไม่สูญเสียข้อมูลแม้แต่วินาทีเดียว

## 4. ผลลัพธ์และการนำไปประยุกต์ใช้จริง

- จัดทำต้นแบบและทดสอบภาคสนาม (Field Test Deployment) ติดตั้งตามจุดจริงในพื้นที่โรงเรียนและชุมชน
- พัฒนาแดชบอร์ดเว็บร่วมกับ React, TypeScript, Tailwind CSS สำหรับแสดงผลกราฟแนวโน้ม และเชื่อมต่อ LINE Messaging API ส่งการแจ้งเตือนค่าฝุ่นเกินมาตรฐานและคำเตือนสุขภาพแก่ครูและนักเรียน
- ส่งผลงานเข้าร่วมการแข่งขัน **NSC 2026** ในหมวดโปรแกรมเพื่อการประยุกต์ใช้งานบนระบบสมองกลฝังตัวและ IoT
