# MedVision AR — แพลตฟอร์ม Web AR ฝึกกู้ชีพและปฐมพยาบาลเบื้องต้น

## 1. ที่มาและความสำคัญ (Motivation & Problem Statement)

ในสถานการณ์ฉุกเฉินที่ผู้ป่วยเกิดภาวะหัวใจหยุดเต้นเฉียบพลัน (Cardiac Arrest) การทำ **CPR (Cardiopulmonary Resuscitation)** ภายใน 4 นาทีแรกเป็นปัจจัยชี้เป็นชี้ตายที่สามารถเพิ่มโอกาสรอดชีวิตได้มากกว่า 2–3 เท่า อย่างไรก็ตาม จากการสังเกตและศึกษาข้อมูล พบปัญหาสำคัญในสังคม 3 ประการ:

1. **ประชาชนทั่วไปไม่มั่นใจในทักษะ**: แม้เคยผ่านการอบรม แต่เมื่อเกิดเหตุการณ์จริงมักเกิดความกลัว ไม่แน่ใจในตำแหน่งการวางมือ และลืมจังหวะความถี่ในการกดหน้าอก
2. **อุปกรณ์ฝึกซ้อมมีราคาสูงและเข้าถึงยาก**: หุ่นฝึก CPR คุณภาพสูงมักมีอยู่จำกัดเฉพาะในโรงพยาบาลหรือศูนย์ฝึกอบรมพิเศษ ทำให้คนส่วนใหญ่ไม่มีโอกาสทบทวนทักษะอย่างสม่ำเสมอ
3. **การดาวน์โหลดแอปพลิเคชันสร้างความยุ่งยาก**: หลายคนไม่อยากติดตั้งแอปพลิเคชันขนาดใหญ่ลงในมือถือเพียงเพื่อการฝึกฝนเป็นครั้งคราว

ด้วยเหตุนี้ **MedVision AR** จึงถูกพัฒนาขึ้นในฐานะ **Web-based Augmented Reality & 3D Interactive Platform** ที่ทำงานผ่านเว็บเบราว์เซอร์ได้ทันทีโดยไม่ต้องติดตั้งแอปพลิเคชัน เพื่อให้ทุกคนสามารถฝึกฝนทักษะการช่วยชีวิตได้ทุกที่ ทุกเวลา ด้วยมือถือเพียงเครื่องเดียว

โครงการนี้ส่งเข้าประกวดและผ่านเข้ารอบ **Semi-Final Round (Top 20 ทีมสุดท้ายระดับประเทศ)** ในเวที **Thailand Metaverse Hackathon** จัดโดยคณะวิศวกรรมศาสตร์ จุฬาลงกรณ์มหาวิทยาลัย

---

## 2. โครงสร้างสถาปัตยกรรมระบบ (System Architecture)

ระบบออกแบบตามแนวคิด **Zero-Installation & Low-Latency 3D** แบ่งการทำงานออกเป็น 4 ชั้นหลัก:

```
┌─────────────────────────────────────────────────────────────────┐
│                    MEDVISION AR SYSTEM FLOW                     │
├─────────────────────┬───────────────────┬───────────────────────┤
│   MOBILE WEB BROWSER│   WEBXR / THREE   │   SUPABASE BACKEND    │
│  Camera Feed Input  │  3D Anatomical    │  User Progress & Auth │
│  Touch / Gyroscope  │  Feedback Engine  │  Telemetry Logs       │
└─────────────────────┴───────────────────┴───────────────────────┘
```

1. **Client Viewport Layer**: สร้างด้วย Next.js (App Router) และ React ร่วมกับ Tailwind CSS มอบประสบการณ์การใช้งานที่ลื่นไหลระดับ Native Web
2. **3D & AR Rendering Engine**: ขับเคลื่อนด้วย Three.js และ WebXR Device API เพื่อเรนเดอร์โมเดลจำลองร่างกายมนุษย์ (Anatomical 3D Torso) แบบเรียลไทม์ ซ้อนทับลงบนพื้นผิวจริงผ่านกล้องสมาร์ตโฟน
3. **Real-Time Interactive Feedback Loop**: ตรวจจับความแม่นยำของจังหวะการกด (BPM), ความลึกจำลอง, และทิศทางการวางมือของผู้ใช้
4. **Backend & Cloud Persistence**: ใช้ Supabase (PostgreSQL + Auth) เพื่อบันทึกประวัติการฝึกฝน คะแนนความแม่นยำ และวิเคราะห์พัฒนาการของผู้เรียน

## 3. วิธีการทำงานและกลไกหลัก (Core Mechanics)

### 3.1 ระบบแนะนำจังหวะการกดแบบเรียลไทม์ (Audio-Visual Metronome)
มาตรฐานสากลของ American Heart Association (AHA) กำหนดให้อัตราการกดหน้าอกอยู่ที่ **100–120 ครั้งต่อนาที (BPM)**:
- ระบบผสานสัญญาณภาพ (Visual Pulse) บนหน้าจอ 3D สอดประสานกับเสียงจังหวะ (Audio Metronome 110 BPM)
- เมื่อผู้ใช้กดหน้าจอกระตุ้นจังหวะ อัลกอริทึมจะคำนวณค่าเบี่ยงเบนเวลา (Timestamp Delta) ระหว่างการกดจริงกับจังหวะมาตรฐาน เพื่อประเมินผลแบบทันที (Perfect / Too Fast / Too Slow)

### 3.2 การจำลองตำแหน่งการวางมือ 3D (Spatial Hand Placement Guide)
- แสดงจุดกึ่งกลางหน้าอก (Lower Half of the Sternum) บนโมเดล 3D ที่สามารถหมุนดูมุมมองรอบทิศทาง (360-degree Orbit)
- แสดงลูกศรจำลองแรงกดในแนวตั้งฉาก 90 องศากับลำตัว เพื่อเตือนสติให้ผู้เรียนล็อคข้อศอกตรงและใช้แรงจากสะโพกตามหลักการแพทย์ที่ถูกต้อง

### 3.3 ระบบ Interactive Gamification & Evaluation
- จำลองสถานการณ์ฉุกเฉินแบบบีบคั้นเวลา (Scenario-based simulation) เช่น ผู้ป่วยหมดสติในสวนสาธารณะ
- ให้คะแนนตามเกณฑ์ 4 มิติ: การประเมินความปลอดภัยของสถานที่, การเรียกขอความช่วยเหลือ (โทร 1669), ความสม่ำเสมอของจังหวะกด, และการปฏิบัติตามขั้นตอนต่อเนื่อง

## 4. ความท้าทายทางเทคนิคและการแก้ปัญหา (Technical Challenges)

### การลดขนาดโมเดล 3D ให้โหลดบนมือถือได้ทันที
- **ปัญหา**: โมเดล 3D กายวิภาคที่มีรายละเอียดสูงมักมีขนาดไฟล์เกิน 30–50MB ทำให้การโหลดผ่านเครือข่ายมือถือ 4G/5G ล่าช้า
- **การแก้ปัญหา**: นำโมเดลเข้ากระบวนการ Draco Compression และ Mesh Decimation ลดขนาด Geometry จนเหลือไม่ถึง 3.5MB โดยยังคงความสมจริงของจุดสังเกตทางกายวิภาคครบถ้วน ทำให้หน้าเว็บพร้อมใช้งานภายในเวลาไม่ถึง 2 วินาที

### การรักษาอัตราเฟรมเรต 60 FPS บนเบราว์เซอร์มือถือ
- จัดการ Memory Lifecycle ของ WebGL Context อย่างรัดกุม ทำลาย Texture และ Geometry ที่ไม่ได้ใช้งานเพื่อป้องกันปัญหา RAM รั่วไหลบนอุปกรณ์สเปกปานกลาง

## 5. ผลลัพธ์และคุณค่าของผลงาน

- ได้รับคัดเลือกผ่านเข้าสู่ **รอบ Semi-Final (Top 20 Teams)** ในการแข่งขัน Thailand Metaverse Hackathon (วิศวกรรมศาสตร์ จุฬาลงกรณ์มหาวิทยาลัย)
